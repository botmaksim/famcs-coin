# Экосистема FAMCS Coin

## Описание проекта
FAMCS Coin — это комплексная экосистема, разработанная для внутреннего использования в рамках факультета (ФПМИ). Проект представляет собой интерактивную платформу, интегрированную в Telegram, которая объединяет элементы геймификации, экономики, голосований и социального взаимодействия. 

Архитектура проекта разделена на надежный серверный бэкенд и быстрый клиентский интерфейс, что обеспечивает отказоустойчивость, безопасность транзакций и отзывчивость пользовательского интерфейса.

## Архитектура и стек технологий

### Инфраструктура
Проект настроен для развертывания через Docker Compose, что обеспечивает изолированность и простоту горизонтального масштабирования.
- **Backend:** Go (Golang) — выбран для обеспечения высокой производительности, безопасной обработки транзакций и интеграции с Telegram Webhooks.
- **Database:** PostgreSQL 15 — реляционная база данных для транзакционной целостности игровой экономики, хранения данных пользователей и конфигураций.
- **Frontend:** React + Vite — легковесный и современный клиентский стек, оптимизированный для работы внутри Telegram Web App (TMA).
- **Networking:** Nginx (раздача статики) и Cloudflare (DDoS защита, проксирование, управление DNS).

### Структура Frontend-приложения
Проект придерживается модульной структуры, основанной на принципах Service-Oriented Architecture (SOA) для клиентской части:
- `/src/api/services` — инкапсулированные сервисы для взаимодействия с REST API (UserService, TasksService, DaoService и т.д.).
- `/src/components` — переиспользуемые UI-компоненты (модальные окна, элементы навигации, карточки).
- `/src/pages` — маршрутизируемые представления, разделенные на TMA (мобильный вид) и Web (полноформатный вид).
- `/src/context` — глобальное управление состоянием (UserContext) для аутентификации и сессий.

## Ключевые возможности

### 1. Telegram Mini App (TMA)
Основной интерфейс взаимодействия пользователей, встроенный непосредственно в Telegram.
- **Модуль "Терминал":** Игровая механика "кликера" с концептуализацией написания кода, расходованием энергии (кофе) и системой пассивного дохода.
- **Магазин (Универ):** Экономический хаб для приобретения апгрейдов ("научных групп") и коллекционных карточек-бустеров, влияющих на параметры аккаунта.
- **Социальные группы (Сквады):** Иерархическая система академических групп с общим фондом (казной) для совместного приобретения временных глобальных бустов.
- **События:** 
  - *Тотализатор:* Система ставок на факультетские события.
  - *Викторина:* Ежедневные технические и олимпиадные задачи с алгоритмической проверкой ответов.
- **DAO и Настройки:** Механизм децентрализованного управления, где пользователи могут инвестировать средства для публикации предложений по развитию системы, а также управлять настройками приватности профиля.

### 2. Социальный движок (Telegram-Бот)
Фоновый сервис, обрабатывающий серверные события и обеспечивающий интерактивность в чатах.
- **Микротранзакции в чатах:** Обработка команд чаевых (например, `/tip`) в публичных чатах с автоматическим проведением транзакции и удалением триггерного сообщения.
- **Система уведомлений:** Асинхронная отправка персонализированных push-уведомлений о событиях в системе (завершение ставок, активация бустов).
- **Реферальная система:** Автоматическая генерация и отправка инвайт-ссылок при попытке взаимодействия с незарегистрированными пользователями.

### 3. Публичный веб-портал
Доступный извне интерфейс для мониторинга экосистемы.
- **Глобальные рейтинги:** Лидерборды игроков и групп, уважающие настройки приватности пользователей.
- **Голосование DAO:** Платформа для просмотра и голосования за инициативы с безопасной авторизацией через Telegram Login Widget.
- **Зал славы:** Прозрачный реестр администраторов платформы.

### 4. Панель управления (Admin Panel)
Защищенный раздел для управления контентом и экономикой.
- Управление правами доступа и назначение модераторов.
- Разрешение конфликтов (возврат средств по ставкам).
- Модерация инициатив DAO и управление контентом событий.

## Дальнейшее развитие и улучшения
В ходе текущей разработки была успешно внедрена сервис-ориентированная архитектура для API-запросов на клиенте. Рекомендуемые шаги для дальнейшего развития:
1. **State Management:** Миграция сложного состояния из Context API на специализированные решения (Zustand или Redux Toolkit) для уменьшения количества ререндеров.
2. **Data Fetching:** Внедрение TanStack Query (React Query) для автоматического кэширования, инвалидации данных и оптимистичных обновлений интерфейса.
3. **Локализация (i18n):** Вынос текстовых констант в отдельные конфигурационные файлы для поддержки мультиязычности.
4. **Тестирование:** Внедрение unit-тестирования для сервисного слоя и утилит с использованием Vitest.
